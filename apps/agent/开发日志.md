## 2026-08-30　add-triage-langgraph-agent（LangGraph 多轮问诊编排）

### 做了什么

用 LangGraph 将问诊建模为状态图：症状采集 → 意图分流 → 急诊判断 → 澄清追问 → 混合检索 → 科室推荐 / 排班·专家 / 兜底。提供 CLI 与 FastAPI `POST /chat` SSE（对齐前端 `web/src/api.ts`）。

### 实现思路

1. **状态图**  
   `ingest → intent`；导诊走 `emergency → check_info → clarify|retrieve → recommend|fallback`；`schedule`/`expert` 分别查 PG 排班与 Milvus 医生；急诊命中短路到 `emergency_exit`。

2. **意图**  
   规则分类 `triage|schedule|expert|other`；澄清上限 2 轮；检索 Top1 分低于阈值走兜底；推荐结果必须来自 `DepartmentRetriever`，不让模型虚构科室。

3. **会话**  
   进程内 `session_id` 字典累积 `symptom_summary` 与 `messages`；多轮澄清后可继续推荐，推荐后再问「有号吗」可走排班分支。

4. **验收**  
   - 胸痛 → `stage=emergency` + high_risk  
   - 「不舒服」→ `clarify`  
   - 「胃痛反酸」→ 推荐消化内科（一）  
   - 澄清后补充症状 → 推荐；再问排班 → 出诊摘要

### 关键产物

| 路径 | 说明 |
|------|------|
| `backend/agent/` | state / intent / nodes / graph / session |
| `backend/agent_cli.py` | 多轮 CLI |
| `backend/api.py` | FastAPI SSE `/chat` |
| `openspec/specs/triage-agent/spec.md` | 能力基线 |

### 建议下一个功能点

**前端联调与会话体验**：用真实 `/chat` 打通 web 对话页；可选将会话落到 Redis/PG，并优化多轮摘要（弱化首轮模糊话术对检索的干扰）。
